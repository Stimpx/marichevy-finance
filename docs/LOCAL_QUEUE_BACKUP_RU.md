# Полная копия устройства через интерфейс v95

В кандидате v95 раздел «Настройки и данные» содержит кнопку **↓ Полная копия устройства**.
На ПК проверьте загрузки, на iPhone — сохранение в «Файлы».
После подготовки остаётся ссылка для ручного скачивания, если автоматическое не сработало. Это запрос браузеру на
скачивание, а не подтверждение записи файла. Реальные Safari/iPhone ещё требуют приёмки.

Копия сохраняет текущее состояние памяти вкладки (`memory_state_json`) и исходные
разрешённые финансовые строки localStorage: primary/pending, base, конфликты,
их архивы, резерв перед импортом и quarantine. Для строк хранилища сохраняются
UTF-8/UTF-16LE SHA-256. Сессия входа и посторонние ключи не читаются.
Серверный резерв в этот файл не входит. При недоступном хранилище или обнаруженном
изменении памяти/ключей/строк во время хеширования скачивание отменяется.
Проверка не является транзакцией между вкладками: заранее остановите правки на устройствах.

Файл частный, не для обычного импорта и не для отправки в чат или staging.
Оригиналы не перезаписывайте. Offline verifier учитывает дополнительное состояние
памяти: его расхождение с сервером/обычным экспортом требует review.
Вымышленное демо имеет отдельные ключи и origin; его копии намеренно не принимаются
как настоящие семейные копии production verifier.

Эта кнопка пока существует только в кандидате, не на опубликованном v94.
Не публиковать новый HTML отдельно от согласованного серверного выпуска ради копирования.
Для действующего v94 ниже сохранён прежний порядок read-only capture.

# Частная копия локальной очереди перед выпуском

Обычный экспорт JSON через интерфейс банка нужен для истории. Он не заменяет
сохранение исходной очереди, общей серверной базы и старых вариантов конфликта.
Для дополнительной копии подготовлен [capture_local_queue.js](../tools/capture_local_queue.js).
Это инструмент для сопровождающего на компьютере; выполнение не требуется
от владельца без отдельного понятного сопровождения.

Скрипт работает только на `https://finance.marichev.pro`. Он читает разрешённые
финансовые ключи localStorage, сохраняет строки без разбора и нормализации,
включая повреждённый JSON, и рассчитывает SHA-256 от UTF-8 и UTF-16LE каждой строки.
Ключ сессии и остальные значения localStorage не читаются. Нет сетевых запросов,
изменений localStorage, очистки очереди или импорта в приложение. Если хранилище
недоступно, выбранные строки изменились во время расчёта или ничего не найдено,
файл не создаётся. Изменения в другой вкладке всё же не дают транзакционной
гарантии: сохранение следует выполнять при остановленных правках на устройствах.

На компьютере, с открытой нужной семьёй в её обычном браузерном профиле:

1. Сначала сохраните обычный JSON через интерфейс банка в частную папку.
2. Дождитесь завершения текущих действий; на время копирования не вносите правки
   в других вкладках и на другом устройстве. Не выходите из аккаунта и не
   очищайте данные сайта.
3. Сопровождающий открывает средства разработчика браузера → **Console / Консоль**,
   проверяет адрес страницы, читает целиком файл скрипта и запускает его содержимое.
   Если браузер запрещает вставку в консоль, остановитесь и выберите другой
   согласованный способ сопровождения. Не отключайте защиту браузера.
4. Проверьте, что браузер действительно сохранил файл
   `marichevy-local-queue-PRIVATE-….json`, а не только показал запрос на скачивание.
   Результат `download-requested` в консоли означает отправленный запрос, не
   подтверждение сохранения файла на диске.
5. Сохраните файл рядом с обычным JSON, отдельно обозначив устройство и профиль
   браузера. Это семейные данные: не отправляйте их в чат, GitHub или тестовый
   Supabase, не прикладывайте к публичным отчётам. Значения сессии не добавляйте.

Формат `marichevy-local-queue-capture-v1` содержит адрес сайта, время по часам
устройства, число ключей и массив `records` с `key`, исходной строкой `raw`, её
длиной в UTF-16, числом байтов UTF-8, `sha256_utf8` и `sha256_utf16le`. Время устройства не проверено
и не определяет, какая из конфликтующих правок верная. UTF-8 рассчитывается
стандартным браузерным TextEncoder; исходная строка хранится в JSON отдельно,
включая экранирование одиночных суррогатных кодовых единиц, если они встречаются.
TextEncoder заменяет одиночный суррогат на U+FFFD, поэтому только хеш UTF-8 не
различает эти строки. Хеш UTF-16LE рассчитан непосредственно от исходных кодовых
единиц без BOM и позволяет проверить их точное сохранение.
Количество ключей может отличаться между v94 и кандидатом. Скрипт сохраняет
существующие ключи и не создаёт отсутствующие.

Этот файл **не является файлом обычного импорта**. Самостоятельно загружать его
в банк не нужно. Восстановление требует проверки исходных строк, ID и связей,
сопоставления с серверной копией и очередями всех устройств, ручного согласования
конфликтующих вариантов, затем согласованного
способа возврата. Скрипт не подтверждает резерв сервера, сохранность всех устройств
или готовность рабочего выпуска.

На iPhone сначала сохраните обычный JSON штатным интерфейсом в **Файлы**.
Это сохраняет экспортируемую историю, но полнота копии локальной очереди iPhone
остаётся непроверенной. Для неё нужен отдельно подготовленный и согласованный
контролируемый способ; инструкции для консоли компьютера на iPhone не применяются.
До проверки очередей обоих устройств их резерв нельзя считать завершённым.


Для доступного владельцу Mac подготовлен подробный порядок подключения iPhone:
[DEVICE_QUEUE_CAPTURE_MAC_RU.md](DEVICE_QUEUE_CAPTURE_MAC_RU.md).
Helper теперь оставляет видимую ссылку скачивания после расчёта хешей. Она остаётся
до следующего успешного захвата или перезагрузки; старый URL освобождается с задержкой,
чтобы не оборвать начатую загрузку. Исходный JSON очереди и сессия не изменяются.
