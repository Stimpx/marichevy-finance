# Проверка PR1 на компьютере и телефоне

Эти инструкции запускают изолированную локальную копию приложения с вымышленными данными. Стенд слушает только `127.0.0.1:8765`; он не публикуется в интернете, а облачная синхронизация отключена. Не используйте реальные пароли, Telegram, семейную историю или экспорт с настоящими данными.

## Получить и запустить на компьютере

Нужен Python 3. Если репозиторий уже есть на компьютере, переключитесь в его корень и получите согласованную ветку:

```sh
git fetch origin codex/pr1-local-data-safety
git switch codex/pr1-local-data-safety
```

Без Git откройте [страницу ветки](https://github.com/Stimpx/marichevy-finance/tree/codex/pr1-local-data-safety), выберите **Code → Download ZIP**, распакуйте архив и откройте терминал в распакованной папке. ZIP должен содержать `tools/serve_staging.py`. Номер GitHub PR для этого не нужен: «PR1» обозначает этап плана, а не заранее назначенный номер Pull Request.

Из корня репозитория запустите пустой тестовый стенд:

```sh
python3 tools/serve_staging.py --fixture
```

На Windows, если команда `python3` не найдена, используйте `py -3 tools/serve_staging.py --fixture`. Откройте `http://127.0.0.1:8765/` в браузере на том же компьютере. Оставьте терминал запущенным; для остановки нажмите `Ctrl+C`.

Cloud workspace нельзя открыть напрямую с вашего компьютера или телефона по `localhost`: адрес `127.0.0.1` всегда означает само устройство, где запущен браузер. Для проверки используйте копию ветки и локальный Python на своём компьютере. Не меняйте адрес прослушивания сервера на `0.0.0.0` и не создавайте публичный preview.

## Проверка записи, экспорта и импорта

1. Введите тестовую запись расхода: сумма `123`, категория, человек и магазин — все значения вымышленные.
2. Нажмите `F5`. Убедитесь, что запись осталась.
3. Экспортируйте JSON из приложения и сохраните его как тестовый файл.
4. Откройте новое окно инкогнито/приватного просмотра на том же компьютере и снова откройте `http://127.0.0.1:8765/`.
5. Импортируйте тестовый JSON в этом окне. Убедитесь, что сумма, категория, человек и магазин совпадают.

Импортируйте только файл, который вы только что создали на этом локальном стенде. Если импортировать заведомо некорректный JSON, приложение должно показать ошибку и оставить текущие данные без изменений.

## Проверка восстановления повреждённого основного состояния (необязательно)

Этот шаг использует DevTools браузера и staging-ключи. Сначала добавьте тестовую запись и сохраните её. Затем добавьте вторую тестовую запись и тоже сохраните: резервная копия должна содержать первую запись. В DevTools Console убедитесь, что `backup` не равен `null` и является корректным JSON. После этого выполните код ниже. Он удаляет только staging-очередь, чтобы восстановление шло именно из резервной копии, и блокирует сохранение при уходе со страницы:

```js
const backup = localStorage.getItem('marichevy_staging_state_backup_v44');
if (!backup) throw new Error('Сначала создайте тестовую резервную копию');
const parsedBackup = JSON.parse(backup);
if (!Array.isArray(parsedBackup?.data?.entries) || !parsedBackup.data.entries.length) {
  throw new Error('В резервной копии ещё нет тестовой записи; остановите проверку');
}
localRecoveryBlocked = true;
localStorage.removeItem('marichevy_staging_pending_v10');
localStorage.setItem('marichevy_staging_state_v10', '{');
```

Перезагрузите страницу. Ожидается восстановление корректной резервной копии; повреждённое исходное значение должно быть сохранено под ключом с суффиксом `_corrupt_v1` при следующем сохранении. Если состояние не восстанавливается, остановитесь и сообщите об этом, не вводя реальные данные. После проверки можно очистить данные сайта для `127.0.0.1` в настройках браузера.

## Проверка на Android

Текущий сервер принимает только соединения с самого компьютера. На Android можно проверить страницу через Chrome с USB-перенаправлением:

1. Включите на Android параметры разработчика и отладку по USB, подключите телефон к компьютеру и подтвердите отладку.
2. Запустите fixture-сервер на компьютере, как описано выше.
3. На компьютере откройте Chrome и перейдите на `chrome://inspect/#devices`. Найдите подключённый телефон и откройте его **Port forwarding**.
4. Добавьте правило: порт устройства `8765` → адрес компьютера `localhost:8765` (в окне может быть поле `Port` и поле `IP address and port`; укажите `localhost:8765`).
5. В Chrome на телефоне откройте `http://localhost:8765/`.

Такой просмотр идёт через подключённый компьютер. Повторите на телефоне проверку записи, экспорта и импорта из предыдущего раздела; вместо F5 обновляйте страницу через меню Chrome. Файл выбирайте из загрузок телефона. Восстановление повреждённого состояния можно проверить через кнопку **Inspect** у страницы телефона в Chrome на компьютере, вставляя staging-код в консоль именно этой страницы. Хранилища компьютера и телефона независимы; облачной синхронизации между ними на стенде нет.

Отключите USB-перенаправление и отладку после проверки. Физический Android в этой среде не проверялся; шаги предназначены для ручной проверки владельцем.

## iPhone и границы проверки

На iPhone нет обычного адреса для доступа к этому loopback-only серверу. Для проверки на iPhone нужен отдельный изолированный HTTPS preview, который в рамках этой задачи не развёрнут и не настроен. Поэтому мобильная проверка на физическом телефоне пока не выполнена.

Этот стенд проверяет локальное поведение интерфейса и хранилища. Он не проверяет реальную авторизацию, Supabase, Telegram, погоду, backend или Cloudflare Preview. При сообщении о проблеме укажите устройство и браузер, действие, ожидаемый и фактический результат. Не прикладывайте реальные записи, учётные данные или скриншоты с личной информацией.
