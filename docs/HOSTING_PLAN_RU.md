# Серверы и дальнейшее размещение финансов · 26 октября 2026

Факты со слов владельца:

- Есть сервер Timeweb.cloud, на нём работает СНТ. Его службы и настройки не менять
  при подготовке финансового приложения.
- Есть второй сервер Firstbyte. Владелец рассматривает его для будущего переноса
  финансов и других проектов. Адреса, ОС, ресурсы и доступы ещё не проверены.
- Рассматривается закрытый Git-репозиторий. Переименование/закрытие репозитория,
  изменение Pages, DNS, серверов и перенос данных сейчас не выполнялись.

## Предлагаемый порядок

1. Завершить кандидат v95 и согласованный общий выпуск backend protocol + HTML.
   Основной сайт остаётся доступен, пока семья вносит траты.
2. Аудитория уточнена: независимые семьи/покупатели, FREE и PRO за 990 ₽.
   Потребуются семейные настройки категорий, имён и часового пояса; нельзя использовать
   одну фиксированную CONFIG.household и общую историю. Период оплаты ещё не определён.
3. Read-only проверить Firstbyte: ОС, свободные ресурсы, существующие сервисы,
   резервирование и восстановление, сетевой доступ и способ безопасного обновления.
   Никаких ключей/паролей в Git, чат, HTML или скрипты установки.
4. Для frontend/своего API подготовить отдельный сайт/службу, отдельные каталоги,
   пользователя и hostname, HTTPS и откат. Не затрагивать СНТ или неизвестные службы.
5. На первом этапе не переносить Supabase/Auth одновременно с изменением хостинга.
   Возможный отдельный перенос БД требует полного проверенного плана: данные,
   аккаунты/сессии, права/RLS, функции, очереди и внешние writers. Текущий закрытый
   roundtrip четырёх app-таблиц не является восстановлением всей платформы Supabase.
6. Перед закрытием/переносом репозитория проверить последствия для GitHub Pages,
   тарифа, домена и автоматической сборки. Подготовить альтернативный работающий
   хостинг до переключения, чтобы не выключить действующий банк.
7. Секреты серверного процесса держать только в защищённых настройках/закрытых
   файлах вне репозитория. Publishable frontend key сам по себе не заменяет Auth/RLS.
   Закрытый репозиторий не является границей доступа к семейной БД.

## Если будут независимые семьи

Для каждой семьи нужны свои membership/данные, приглашения и права; сервер обязан
проверять членство для каждого чтения и изменения. Успешные текущие проверки двух
фиктивных семей — основа, а не готовый публичный многопользовательский сервис.
Понадобятся семейный onboarding, управление участниками, восстановление доступа,
удаление/выгрузка данных и проверяемые резервные копии. Нельзя открывать действующую
семейную историю как общедоступное демо.

Эта запись сохраняет пожелание владельца и план для review. Она не является
разрешением на изменение серверов, публичность репозитория или перенос истории.
Итоговое разрешение на конкретный рабочий выпуск запрашивается после готовности.
