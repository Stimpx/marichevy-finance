# PR1: локальное хранение, резервные копии и импорт

База: `bfc7ce5`, v94-expense-buckets. Изменения подготовлены только в ветке `codex/pr1-local-data-safety`.

Исправлено:

- При повреждении основной копии приложение читает корректную очередь или резервную копию. Если восстановление невозможно, запись блокируется: пустое состояние не заменяет повреждённые данные.
- Перед заменой повреждённого значения его исходные байты сохраняются отдельно с суффиксом `_corrupt_v1`. Резервная копия предыдущего подтверждённого состояния сохраняется независимо от новой записи. Если безопасное резервирование невозможно, операция сообщает об ошибке.
- Ошибки основной записи, очереди и копии перед импортом больше не выдаются за локальный успех. Форма расхода сохраняет введённые значения при сбое. Уведомления других разделов также не скрывают ошибку хранилища.
- Импорт сначала проверяет структуру, типы и необходимые поля вложенных записей, затем сохраняет копию для отката. При ошибке локальной фиксации восстанавливаются предыдущее состояние и значения основной копии/очереди/резерва; при невозможности отката дальнейшая запись блокируется.
- ID и другие данные больше не вставляются в исполняемые inline-обработчики. Списки операций, целей, дат, дел, сообщений, лимитов, регулярных планов и счетов используют JSON-данные атрибутов и фиксированный набор обработчиков. Экранируются значения редактора; служебные ключи объектов не допускаются при импорте.

Совместимость: имена ключей production-хранилища и формат JSON не менялись; категории и участники не ограничены списком, отсутствующий `beneficiary` не добавляется в старые записи. Дополнительные поля операций сохраняются. Импорт не переименовывает исторические категории, не пересчитывает суммы и не выполняет миграцию. Повреждённые или структурно некорректные файлы отклоняются целиком; это намеренное ограничение вместо молчаливого частичного импорта.

Проверки: 28 браузерных регрессий на вымышленных данных проходят; на исходном HTML те же проверки выявляют 26 упавших тестов (23 первоначальных проверки и 5 добавленных проверены отдельно). Ещё 3 теста проверяют HTTP-изоляцию staging. Оба скрипта JavaScript проходят проверку синтаксиса, CSS-блоки совпадают с исходными. Подробности и команды — в `tests/README.md`; ручная локальная проверка — в `docs/PR1_TESTING.md`.

Локальный staging отключает backend в выдаваемом HTML, использует отдельные ключи хранения и запрещает сетевые соединения CSP. Это не опубликованный Cloudflare Preview и не проверка настоящего Supabase. Новые библиотеки не устанавливались.

Остаётся за пределами PR1:

- Гонки двух устройств, серверная проверка версии, идемпотентность платежей и полноценная проверка облачного подтверждения относятся к PR2. Здесь изменена только обработка ошибок локальных записей в существующих путях, не протокол синхронизации.
- Финансовые расчёты, формы/дизайн, RLS, Edge Functions, DNS и выпуск на основной сайт не изменяются.
- localStorage ограничен квотой, доступностью браузера и его очисткой. Резерв в том же браузере не заменяет внешний JSON-экспорт; при отказе всех копий новая история остаётся только в памяти вкладки. Повторно добавлять её не следует — нужно скачать JSON и не закрывать вкладку.
- Проверка на настоящей истории и Safari/Яндекс Browser не проводилась. Реальные семейные файлы, пароли, Supabase и Telegram в тестах не использовались.

Для отката изменений кода используется предыдущий коммит/отмена этого PR. Автоматические операции с настоящими данными не выполнялись; восстановление пользовательского JSON и публикация требуют отдельного решения владельца.
