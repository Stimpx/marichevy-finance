## Фактическая рабочая схема и подготовленные исправления

Read-only inventory и отдельный строго ограниченный review функции членства
выполнены через `PRODUCTION_SUPABASE_INSPECTION_TOKEN`. Семейные/auth строки и
API keys не читались. Рабочая база PostgreSQL 17.11, таблицы `family_state`,
`households`, `household_members`, `family_chore_deliveries`, RLS включён.
001 совместима с подтверждёнными четырьмя колонками, NOT NULL и внешними ключами.

Членство проверяется SECURITY DEFINER helper с двумя UUID; пять политик
передают `auth.uid()`. Обнаружены лишние TRUNCATE/TRIGGER у клиентских ролей
и возможность вызвать lookup для произвольного user UUID. Это каталоговые
факты; доступный анонимный HTTP endpoint TRUNCATE не установлен.

Подготовлены `002_restrict_table_capabilities.sql` и
`003_bound_membership_lookup.sql`: снять лишние возможности, закрыть анонимный
lookup и связать обычный lookup с текущим пользователем. Контракт service_role
сохранён. Guard отказывается менять неизвестные функции/политики/права.
`staging_membership_v2.sql` развивает только известную синтетическую fixture,
воспроизводит фактическое членство/FK/NOT NULL и сохраняет семейный JSON/revisions.
Эти новые SQL пока **не применены в production**; hosted проверка v2 успешно завершена.
Подробности — [PRODUCTION_SCHEMA_FINDINGS.md](PRODUCTION_SCHEMA_FINDINGS.md).

## Исправления этого продолжения

Трёхстороннее сравнение с подтверждённой серверной базой заменяет выбор по часам.
Основная локальная копия и pending также сравниваются с базой после частичного
сбоя записи. Неоднозначность блокирует отправку и сохраняет обе копии.
Отложенные refresh/login/verify ответы после logout не восстанавливают сессию.
Различные нерешённые серверные варианты архивируются; выгрузка включает
`previous_conflicts`, одинаковый повтор не наращивает архив. Вход дополнительно
проверяет доступ к настроенной семье до открытия кэша. Неизвестные поля дел и
прочие совместимые JSON-расширения сохраняются.

Конфликт не разрешается автоматически. Частный пакет через «Скачать варианты
конфликта» предназначен для согласования, не для обычного JSON-импорта. Полного
редактора конфликтов нет; семейные очереди нужно согласовать до перехода.
Пользователь браузерного профиля с доступом к его localStorage остаётся доверенным;
на общем компьютере нужны отдельные профили.
