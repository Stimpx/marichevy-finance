# Единый справочник покупок и категорий · проект для согласования

Цель: одна и та же покупка не меняет категорию из-за варианта написания.
Категория отвечает «на что», уточнение — какой товар/услуга, место — магазин,
получатель — для кого, заметка — дополнительный текст владельца. Автор ввода
не является автоматически получателем покупки.

## Что уже исправлено в кандидате

- ChatGPT/OpenAI предлагают существующие Подписки/Работа; общий термин «подписка»
  больше не ведёт к развлечениям. Назначение выбирает владелец.
- Подгузники/памперсы предлагают существующую категорию Дети с понятной подписью
  «Детские товары»; явное указание взрослых/животных учитывается отдельно.
- КБ/Красное & Белое, Детский мир, Familia и другие известные варианты имеют
  локальные алиасы. Название магазина не определяет автоматически категорию:
  в одном магазине продаются разные товары.
- Поисковое «од» и совпадающий с уточнением префикс не превращаются в заметку.
  Полное название покупки сохраняется один раз, собственная заметка не затирается.
- Общие авто-записи не теряются: они видимы «Без уточнения», явное такси относится
  к передвижению. У всех экранов одно правило. Получатели не переназначаются.

## Что требуется свести с перечнем семьи

Владелец сообщил, что жена пришлёт дополнительные требования. До окончательного
справочника не выполняется массовая перекатегоризация настоящей истории.
Пример неоднозначности: «Вкусняшки», «пиво» и «Продукты». Нужны единый родительский
раздел и понятные уточнения; голое старое слово «Вкусняшки» без описания не доказывает,
что была куплена та же вещь. Название КБ само по себе не доказывает покупку алкоголя.
Такие записи не исправляются по догадке. Точный состав родительских разделов и
уточнений будет сведен с финальным перечнем семьи, без новых участников по расшифровке голоса.

## Безопасное исправление прежних расходов после согласования

1. Источник — свежая рабочая база и проверенные очереди устройств на момент выпуска,
   а не прежний дамп. Пока семья добавляет траты, рабочий сайт сохраняет их обычным
   способом; эта разработка не ведёт фоновое зеркало и не заменяет живую историю.
2. В закрытой среде готовится явный план по существующим ID: исходная категория,
   предлагаемая категория/уточнение и фиксированное основание. Неясные строки — review.
   Финансовые записи не попадают в демо, тестовый Supabase, Git и чат.
3. Для каждого изменения сохраняются ID, сумма, дата, участники, место, оригинальный
   текст и неизвестные поля; сохраняется происхождение старой классификации.
   Проверяются состав операций, суммы в точных копейках, связи долгов/рассрочек,
   tombstones и неизменность всех полей, кроме согласованной классификации.
4. Массовое применение не разрешено до закрытия очередей, проверки плана и одного
   итогового разрешения на согласованный server+HTML выпуск. Перед записью сверяются
   актуальная revision/источник; новые операции не перезаписываются старым снимком.
5. При расхождении источник сохраняется целиком; автоматического удаления дублей,
   выбора конфликтов по часам или повторного создания расходов нет.

Текущий кандидат исправляет подсказки и расчёты, но не объявляет настоящую историю
уже перекатегоризированной. Подготовленный частный server restore — проверка
сохранности четырёх app-таблиц, а не разрешение менять историю.

## Отложенная сверка семейного справочника

Ожидаем конкретный список семьи. Группировки, бюджеты и прежние записи сейчас
не меняются. Для новых покупок уже есть подсказки, но отдельного экрана массовой
проверки прежних категорий пока нет; доступно редактирование отдельных операций
из истории и расшифровки аналитики.

Замечания для следующего согласования:

- В форме «Подписки и сервисы» сохраняются как `Подписки`, а аналитическая группа
  пока называется «Досуг и привычки». `Работа` относится к «Прочее». Даже правильный
  выбор для ChatGPT может выглядеть непонятно на уровне родительского раздела.
- Названия `EXPENSE_GROUPS.title` используются в сохранённых
  `intelligence.budgets[].group`. Их нельзя просто переименовать без сохранения
  связи с действующими семейными бюджетами.
- Одинаковые магазин и сумма не доказывают одинаковый товар. КБ не означает
  автоматически алкоголь; «Вкусняшки» без описания не доказывают покупку пива.
  Неоднозначные записи остаются на ручной проверке.

Минимальный следующий вариант — предварительный список: существующая операция,
старая категория, варианты новой категории и понятное основание. Например,
ChatGPT — «Подписки» либо «Работа» по выбору семьи; подгузники — с учётом явно
указанного детского, взрослого или животного назначения. Выбор изначально пустой.
Сумма, дата, получатель, магазин, текст и неизвестные поля сохраняются. Связанные
кредитные и регулярные платежи в первую массовую сверку не включаются. Любое
будущее применение потребует отдельной проверки актуальных ID и неизменности
проверяемых записей; этот текст не описывает уже выполненную перекатегоризацию.
