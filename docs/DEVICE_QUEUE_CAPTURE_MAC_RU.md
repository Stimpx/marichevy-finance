# Частная копия очередей v94 с iPhone и ПК

Этот порядок нужен для уже опубликованного банка v94 на
`https://finance.marichev.pro`. Публиковать v95 для получения копии не нужно.
Разрешение владельца на закрытое резервирование и локальную проверку уже дано.
26 октября владелец прошёл этот порядок на исходной вкладке Safari iPhone:
подтверждены включённый Web Inspector, origin/visible в удалённой консоли,
панель capture и штатный запрос загрузки. Затем владелец подтвердил загрузку,
показал файл в своих «Файлах»/iCloud Drive и сообщил его ненулевой размер.
Содержимое, хеши, восстановление, доступность без сети и дополнительная копия
на Mac ещё не проверены. Это получение файла по интерфейсу/сообщению владельца,
а не закрытая сверка с сервером или приёмка выпуска. Ни исходники семьи,
ни их размеры/имена/пути/ID в эту инструкцию не добавлены.

Используется проверенный локальный файл
[capture_local_queue.js](../tools/capture_local_queue.js). Сопровождающий сначала
читает его целиком. Скрипт читает только разрешённые финансовые строки хранилища,
включая очередь, резервные и конфликтующие варианты. Он не читает сессию входа,
не отправляет запросы, не меняет localStorage и не объединяет данные.

## До подключения устройств

1. На время копирования остановите правки банка на всех устройствах и вкладках.
   Дождитесь окончания текущих действий. Не выходите из аккаунтов, не очищайте
   данные сайта, не выполняйте импорт и не переустанавливайте приложение.
2. Для каждого устройства отметьте, где именно открыт банк: например,
   `iPhone-Safari-обычный-профиль` и `ПК-Яндекс-обычный-профиль`.
   Другая вкладка, частный режим или новый профиль не заменяют исходный профиль.
3. Сохраните обычный JSON через **Данные → Резервная копия JSON**. Проверьте сам
   файл: на iPhone — в **Файлы**, на ПК — в частной папке. Если файл уже сохранён
   и с тех пор правок не было, сохраните его как исходник; не перезаписывайте.
4. Подготовьте на компьютере владельца частную папку с отдельными подпапками для
   каждого устройства/профиля. Файлы настоящей семьи не прикрепляются к чату,
   GitHub, демо, тестовому Supabase или образу облачной среды.

## iPhone: подключить его страницу к Safari на Mac

1. Подключите разблокированный iPhone кабелем к доверенному Mac. При запросе
   «Доверять этому компьютеру?» подтвердите доверие на своём устройстве.
   Код разблокировки никому не сообщайте.
2. На iPhone включите **Настройки → Приложения → Safari → Дополнения →
   Веб-инспектор**. На старых версиях iOS путь начинается с
   **Настройки → Safari**; раздел может называться **Дополнительно / Advanced**,
   а переключатель — **Web Inspector**.
3. На Mac откройте **Safari → Настройки → Дополнения / Advanced**. Включите
   **«Показывать функции для веб-разработчиков»** или, в другой версии Safari,
   **«Показывать меню „Разработка“ в строке меню»**. Должно появиться меню
   **Разработка / Develop**. Настройка Remote Automation для этого не нужна.
4. На iPhone оставьте открытой именно привычную страницу банка с нужной семьёй.
   Проверьте адрес `https://finance.marichev.pro`. Не открывайте для проверки
   пустой частный профиль или обезличенное демо.
5. На Mac выберите **Разработка → ваш iPhone → нужная страница
   finance.marichev.pro**. Откроется инспектор страницы телефона.
   Если страниц несколько, сопоставьте выбранную с открытой на телефоне.
   Консоль собственной вкладки Mac читает хранилище Mac, а не iPhone.

Если банк обычно открывается отдельной иконкой с домашнего экрана iPhone,
сопровождающий должен выбрать именно это приложение/его страницу в инспекторе.
Копия другой вкладки Safari не доказывает сохранность очереди установленного
веб-приложения. Если нужная страница или профиль не появляются, остановитесь
с результатом `blocked`: не создавайте новый профиль и не переносите в него данные.

## iPhone: сохранить исходную очередь

1. Сопровождающий проверяет выбранное устройство, вкладку и точный адрес сайта,
   открывает **Console / Консоль** инспектора iPhone и запускает целиком содержимое
   заранее прочитанного локального `tools/capture_local_queue.js`.
   Не используйте вместо него команды загрузки чужого скрипта из интернета.
2. Если браузер запрещает вставку, остановитесь. Не вводите команды разрешения
   вставки и не отключайте защиту браузера. Сообщите только, что вставка заблокирована.
3. После подготовки копии скрипт запрашивает скачивание. На странице остаётся
   видимая ссылка для ручного скачивания частной копии: если автоматическое
   скачивание не началось, нажмите её **на самом iPhone**.
4. Найдите файл `marichevy-local-queue-PRIVATE-….json`. Проверьте **Файлы → Загрузки**
   и список загрузок Safari; при удалённой работе проверьте также загрузки Mac.
   Если Safari открыл документ вместо скачивания, используйте **Поделиться →
   Сохранить в Файлы** и выберите свою частную папку.
5. Убедитесь, что сохранён именно файл и загрузка завершена. Сообщение
   `download-requested` в консоли и появление ссылки сами по себе этого не доказывают.
   Не отправляйте содержимое документа и снимки настоящей истории в чат.
6. Сохраните raw-файл рядом с обычным JSON того же iPhone/профиля. Перенос с телефона
   на свой Mac допустим штатным частным способом, например AirDrop на свой Mac или
   через кабель. Не используйте для передачи чат, Git или тестовый сервер.

Ссылка содержит частный снимок: не оставляйте экран открытым посторонним.
Она удаляется при следующем запуске скрипта или перезагрузке страницы.
Не перезагружайте страницу только ради её удаления до проверки скачанного файла.
Повторный запуск не очищает очередь; ранее сохранённые файлы оставляйте отдельно.

## ПК Windows: сохранить очередь своего браузера

1. Откройте банк в том же браузере и профиле, которым пользуетесь обычно.
   Проверьте адрес `https://finance.marichev.pro` и нужную семью.
2. Сопровождающий открывает **F12 → Console / Консоль** и запускает целиком
   заранее прочитанный локальный `tools/capture_local_queue.js`.
   При запрете вставки остановитесь, не отключая защиту.
3. Проверьте настоящее скачивание `marichevy-local-queue-PRIVATE-….json`.
   При необходимости нажмите оставшуюся на странице ссылку скачивания.
4. Положите файл рядом с обычным JSON именно этого ПК/профиля.
   Сохранённая очередь ПК не заменяет очередь телефона и наоборот.

Для дополнительного устройства или браузерного профиля нужна своя пара файлов.
Не считайте очередь Android скопированной из Safari: такой профиль проверяется
отдельно поддерживаемым способом. До этой проверки его статус — `blocked`,
а данные приложения остаются на месте.

## Что сообщить сопровождающему

Достаточно короткого результата без истории и её снимков, например:

```text
iPhone / Safari: done — обычный JSON и raw-файл действительно сохранены.
ПК / Яндекс: done — оба файла сохранены.
```

При остановке укажите только `blocked` и причину: «телефон не виден в Develop»,
«нужная вкладка не видна», «вставка запрещена», «файл не появился» или фиксированный
код ошибки скрипта. Финансовые суммы, идентификаторы семьи, токены и содержимое
localStorage сообщать не нужно. `done` подтверждает получение файлов, а не
успешное восстановление, согласование конфликтов или разрешение выпуска.

## Закрытая локальная проверка файлов

Оригиналы не редактируются и не загружаются в банк. Сопровождающий сопоставляет
пары «обычный JSON + raw» каждого подтверждённого устройства с серверным снимком
и отдельным результатом восстановления. Порядок и формат частного `plan.json` —
[PRIVATE_RESTORE_ACCEPTANCE.md](PRIVATE_RESTORE_ACCEPTANCE.md).
Владельцу не нужно вручную редактировать JSON, UUID или строки очереди.

Существующий `tools/verify_private_backup.py` работает локально, без сети и
изменения файлов. Он проверяет исходные строки и хеши, очередь, конфликтующие
варианты, ID, связи и точные денежные значения. Непустая очередь требует проверки
подтверждения сервером; одинаковые JSON не дают права удалить её.

Проверка выполняется на компьютере владельца либо через заранее согласованный
закрытый канал вне чата. В одной частной папке должны быть явно выбранные входные
файлы и подготовленный сопровождающим plan. Папка — вне checkout, доступ только
владельцу (`0700`), выбранные файлы и отчёт — `0600`; это ограничение доступа,
не шифрование. Пример команды для сопровождающего на Mac, с путём к этой папке
вместо `PRIVATE_FOLDER` и новым именем отчёта:

```sh
umask 077
set -C
python3 tools/verify_private_backup.py --manifest PRIVATE_FOLDER/plan.json --allow-private-input > PRIVATE_FOLDER/verification-PRIVATE.json
```

Отчёт, хеши и исходники остаются в частной папке. В чат передаётся только
`passed`, `review_required` или `failed` и необходимые фиксированные коды без данных.
Если закрытого способа сопоставить файлы пока нет, они остаются у владельца,
а проверка устройств не объявляется завершённой. Получение этих файлов
не разрешает публикацию сервера или HTML.
