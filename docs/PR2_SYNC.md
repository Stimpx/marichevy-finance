# PR2 — защищённая синхронизация

Зависит от PR1. Код клиента и SQL подготовлены для проверки; рабочий Supabase не изменён.

Клиент заменяет перезапись всего JSON без проверки версии на RPC compare-and-swap. При конфликте читает новую серверную версию, объединяет операции и удаления и повторяет запись не более пяти раз. Очередь локальных изменений удаляется только после подтверждения точного снимка, идентификатора запроса и новой версии. Изменения, сделанные во время HTTP-запроса, остаются в очереди. Ошибка чтения, записи или неполный ответ не дают статуса «Синхронизировано».

Проверяются операции, цели, события, заметки, дела, рассрочки, лимиты, регулярные платежи, счета и удаления. Неизвестные JSON-поля сохраняются как непрозрачные расширения; их собственные правила конфликтов не изобретаются. Новые подтверждения регулярных платежей и частей рассрочки получают устойчивый ID; компоненты ID кодируются, чтобы разделитель внутри импортированного ID не создавал коллизий. Прежние UUID, категории и участники остаются без изменений; дубли в старой истории автоматически не удаляются.

Старая схема/протокол облака допускают чтение, но блокируют новые облачные записи в этом клиенте. Изменения остаются на устройстве до согласованного обновления сервера. Возврат к небезопасному POST не предусмотрен. Поэтому этот клиент **нельзя выпускать как обычное обновление** без отдельной проверки и подготовки сервера.

SQL, ограничения доступа, активация одной семьи и откат описаны в [SYNC_SERVER.md](SYNC_SERVER.md). Выполнены 15 проверок настоящего изолированного PostgreSQL. Браузерные проверки используют два независимых контекста и синтетический RPC; реальные сетевые запросы заблокированы.

Остаётся проверить отдельно разрешённый Supabase staging: фактическую схему, RLS, права, другие пути записи, PostgREST и сценарий обновления обоих устройств. Конфликт правки одного объекта разрешается существующими метками времени; неверные часы устройств и семантика неизвестных расширений остаются ограничениями. Гарантия CAS действует только после активации протокола 2 и блокировки старых записывающих клиентов.
