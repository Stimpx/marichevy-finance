## Поведение сайта

- Банковский остаток и две подтверждённые оплаты 2 ноября видны сразу; новые
  расходы при загрузке графика не создаются.
- «Учесть оплату из истории» сохраняет распределение тела, процентов,
  начислений и досрочной части в самой существующей операции. Изменение её
  суммы/даты требует повторной проверки распределения.
- Досрочная часть не подтверждает следующий обязательный платёж. По двум
  описанным обязательствам в ноябре ещё предстоят 85 885 ₽ и 4 608 ₽.
- Будущие оплаты автоматически пересчитывают остаток и прогноз. Банковский
  срез и будущий сценарий разделены. Наступившая дата не означает оплату.
- В день банковской сверки явно выбирается, включено ли списание в срез.
  Новая сверка включает прежние оплаты; повторное сохранение распределения
  после неё не вычитает досрочную сумму второй раз.
- График сохраняет каждую фактическую точку, использует календарную ось,
  ограниченные периоды 1/3 года и отдельную линию будущих платежей. Точки
  доступны мышью, клавиатурой и через список. На телефоне журнал показывает
  остаток каждой оплаты без обязательной горизонтальной прокрутки.
- Полное погашение тела не объявляет оплаченные проценты без сверки. Варианты
  с неизвестными/уже отдельно уплаченными промежуточными процентами требуют
  подтверждения, вместо повторного начисления или ложного закрытия.
- Строка досрочного сценария, карточки итогов и графики перестраиваются по
  доступной ширине, включая масштаб 200%.

Семейный клиент добавляет этот план после входа владельца/редактора и успешного
полного чтения текущей семьи из облака. Добавление сохраняется обычным CAS в
том же цикле синхронизации. Похожие даты/суммы требуют проверки; точное
совпадение существующего графика, его ID/источник и tombstone предотвращают
повторное добавление. Стабильный ID сохраняет один план на двух устройствах.

Ни первоначальная покупка, ни прошлые оплаты не выдумываются. Способ учёта
расходов для будущего подтверждения остаётся явным выбором существующего
платёжного процесса. Ошибка локального сохранения допускает повторную попытку
без второго плана. Фактический ACK сервера семьи после входа владельца не
выдаётся за результат локального теста: серверный финансовый JSON в этой
работе не читался, административный SQL не выполнялся.
